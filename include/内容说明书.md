# 银行系统模拟 —— 内容说明书

---

## 一、系统架构概述

本系统模拟了一个多用户银行的核心业务，底层使用 C++17，基于 OOP 设计范式实现。整体架构分为三层：

```
┌─────────────────────────────┐
│   Command Layer  (命令层)    │  ← 输入解析、参数校验、命令路由
├─────────────────────────────┤
│   Business Layer (业务层)    │  ← BankSystem: 账户管理、交易、利息、日志、持久化
├─────────────────────────────┤
│   Domain Layer  (领域层)     │  ← Account/Date/User/InterestCalculator 等核心领域对象
└─────────────────────────────┘
```

类与类之间的关系（文字描述）：

```
BankSystem
 ├─── 1:1 ─── Date currentDate          (系统当前日期)
 ├─── 1:N ─── User                      (用户列表，每个用户关联多个账户ID)
 ├─── 1:N ─── Account* (多态)           (账户列表，指向 SavingAccount 或 CreditAccount)
 └─── 1:N ─── string logRecords          (操作日志)

Account (抽象基类)
 ├─── SavingAccount                      (储蓄账户，实现存款/取款)
 └─── CreditAccount                      (信用账户，含信用额度，实现存款/取款)

Command ─── 1:1 ─── BankSystem&          (命令类持有系统引用，委托执行)

InterestCalculator (静态工具类)           (利息计算，被 Account::updateInterest 调用)
Tools (静态工具类)                        (输出格式化、金额格式化)
```

### 2.1 Date 类 —— 日期

**文件**: `date.h` / `date.cpp`

#### 数据成员

| 成员 | 类型 | 访问 | 说明 |
|------|------|------|------|
| `year` | `int` | private | 年份，合法范围 1~无穷 |
| `month` | `int` | private | 月份，1~12 |
| `day` | `int` | private | 日，1~该月最大天数 |
| `totalDays` | `int` | private | 从公元1年1月1日起的累计天数，用于快速计算日期差和星期 |
| `weekName[7]` | `static const string` | private | 星期名称数组：Sunday~Saturday |
| `monthName[13]` | `static const string` | private | 月份名称数组（1-based），`monthName[0]=""` |
| `daysBeforeMonth[13]` | `static const int` | private | 每月之前累计天数，如 `daysBeforeMonth[2]=31` |

#### 函数成员

| 函数 | 原型 | 说明 |
|------|------|------|
| `Date()` | 默认构造 | 初始化为 1970-01-01，`totalDays=719163`（1970-01-01距离公元1-1-1的天数） |
| `Date(y,m,d)` | 有参构造 | 若日期非法则 `throw std::invalid_argument`；合法则计算 `totalDays`（含闰年修正） |
| `isLeapYear(y)` | `static bool` | 闰年判断：能整除4且不能整除100，或能整除400 |
| `daysInMonth(y,m)` | `static int` | 返回指定年月天数，2月闰年29天平年28天 |
| `isLegalDate(y,m,d)` | `static bool` | 日期合法性校验：月1~12，日1~当月最大天数 |
| `daysInYear()` | `int` | 返回该年总天数（闰年366，平年365） |
| `getMaxDay()` | `int` | 返回当前月份最大天数 |
| `addDays(n)` | `bool` | 日期前进 n 天（n>0），逐月进位；失败返回 false |
| `setDate(y,m,d)` | `bool` | 设置日期（只能前进不能后退），若新日期 ≤ 当前日期则失败 |
| `operator-(other)` | `int` | 返回两日期间隔天数 |
| `showDate()` | `bool` | 输出日期，格式：`Wednesday, January 1, 1970` |

#### 技术亮点：totalDays 日期计算法

不使用标准库，通过 `totalDays`（公元1年1月1日起的累计天数）实现：
- **日期差**：直接 `totalDays` 相减，O(1)
- **星期**：`totalDays % 7` 直接得到星期索引
- **闰年处理**：`years*365 + years/4 - years/100 + years/400` 精确计算闰年带来的额外天数

### 2.3 Account 类族 —— 账户（多态层次）

**文件**: `account.h` / `account.cpp`

#### 基类 Account（抽象类）

**数据成员**：

| 成员 | 类型 | 访问 | 说明 |
|------|------|------|------|
| `id` | `int` | protected | 账户唯一ID |
| `name` | `string` | protected | 账户名称 |
| `type` | `char` | protected | 账户类型，'S' 储蓄 / 'C' 信用 |
| `balance` | `double` | protected | 账户余额（信用账户可为负） |
| `openDate` | `Date` | protected | 开户日期 |
| `lastInterestDate` | `Date` | protected | 上次计息截止日期 |
| `interest` | `double` | protected | 未结息的累计利息 |

**函数成员**：

| 函数 | 说明 |
|------|------|
| `Account(id,type,name,balance,openDate)` | 构造，初始化列表按声明顺序对齐 |
| `virtual ~Account() = default` | 虚析构，确保派生类通过基类指针正确析构 |
| `deposit(date,amount)` | **纯虚函数**，存款，由派生类实现 |
| `withdraw(date,amount)` | **纯虚函数**，取款，由派生类实现 |
| `updateInterest(targetDate)` | 计息核心算法（见"技术难点"章节） |
| `settleMonthlyInterest()` | 按月结息：`balance += interest; interest = 0` |
| `modifyName(newName)` | 修改账户名称 |
| 各 getter | `getId()` / `getType()` / `getName()` / `getBalance()` / `getOpenDate()` |

#### SavingAccount（储蓄账户）

- `type` 硬编码为 `'S'`
- `deposit`: `amount >= 0` 即可存入
- `withdraw`: `0 <= amount <= balance` 即可取出

#### CreditAccount（信用账户）

- `type` 硬编码为 `'C'`
- `credit`（private）: 信用额度，构造时 `balance=0`，信用额度独立存储
- `deposit`: `amount >= 0` 即可存入
- `withdraw`: `0 <= amount <= balance + credit`，允许透支
- `modifyCredit(newCredit)`: 修改信用额度
- `getCredit()`: 返回信用额度

#### 技术亮点：多态策略模式

Account 使用纯虚函数 + 派生类实现不同行为：
- 储蓄/信用账户的 deposit/withdraw 逻辑不同，通过多态统一调用
- BankSystem 通过 `Account*` 指针操作所有账户，无需判断具体类型
- 当需要区分类型时（如 query 显示信用额度），用 `static_cast` 安全下行转换

### 2.4 InterestCalculator 类 —— 利息计算器

**文件**: `interestCalculator.h` / `interestCalculator.cpp`

#### 静态常量（年利率）

| 常量 | 值 | 含义 |
|------|-----|------|
| `savingRate` | 0.0115 (1.15%) | 储蓄活期年利率 |
| `creditRate` | 0.0225 (2.25%) | 信用账户正余额年利率 |
| `debtRate` | 0.0005 (0.05%/日) | 信用账户透支日罚息率 |

#### 核心函数

`calcDailyInterest(type, balance, date)`:
- 储蓄账户 `'S'`: `日利率 = 1.15% / daysInYear`，按年化计息
- 信用账户 `'C'`:
  - balance ≥ 0: `日利率 = 2.25% / daysInYear`（活期计息）
  - balance < 0: `日利率 = 0.0005`（透支日罚息，非年化）
- 返回 `balance × 日利率`

### 2.7 Command 类 —— 命令解析与路由

**文件**: `command.h`

#### 职责

1. 接收原始命令字符串
2. 解析命令关键字和参数
3. **类型校验**：通过 `>>` 操作符的返回值判断每个参数是否能正确解析为期望类型
4. **正整数校验**：`isPositiveInt(s)` 对 ADD_DAY / SET_DATE / ROLLBACK 的参数做严格的数字字符检查
5. 委托给 `BankSystem` 相应方法执行

#### 设计决策：严格参数校验

```cpp
if (!(iss >> id >> type >> accountName >> balance)) {
    Tools::printFailure(); return;
}
```

- 任何参数类型不匹配或缺失 → 立即失败
- 与 BankSystem 的业务校验形成**两层防护**：Command 验证"能不能解析"，BankSystem 验证"逻辑合不合法"

#### 校验辅助函数

`isPositiveInt(s)`: 逐字符检查是否为 0-9 数字，排除空字符串、负数、浮点数

## 三、主要技术难点与实现方案

### 3.1 日期系统与累计天数算法

**难点**：需要支持任意跨年跨月的日期计算、闰年判断、星期推算，且不能依赖标准库时间函数。

**方案**：
- 使用 `totalDays`（从公元1年1月1日起累计天数）作为内部表示
- 闰年修正公式：`years/4 - years/100 + years/400`（分别对应每4年一闰、每100年不闰、每400年再闰）
- 日期差 O(1)：直接 `totalDays` 相减
- 星期 O(1)：`totalDays % 7` 直接索引
- 月份进位使用 `daysBeforeMonth[]` 查表，避免循环累加

### 3.2 利息计算与按月复利

**难点**：模拟银行实际计息规则——活期按年化利率每日计息，每月1日结息入账（复利），日期跳跃式前进时需逐日累计。

**方案（`Account::updateInterest`）**：

```
从 lastInterestDate 开始，逐日迭代至 targetDate：
  对每一天 current：
    1. 计算当日利息（日利率 × 当日余额）
    2. 累加到 interest 变量
    3. current.addDays(1) 前进到下一天
    4. 若新日期的 day == 1（进入新月），调用 settleMonthlyInterest()
       将累积利息加入余额，归零 interest
  更新 lastInterestDate = targetDate
```

**关键细节**：
- 闰年处理：日利率 = 年利率 / 当年天数，`daysInYear()` 自动处理 366/365
- 日期只能前进（`setDate` 拒绝后退），避免利息重复计算

### 3.3 多态账户体系与虚析构

**难点**：`BankSystem` 通过 `vector<Account*>` 统一管理储蓄和信用两种账户，需要安全的多态操作和内存管理。

**方案**：
- Account 定义纯虚函数 `deposit` / `withdraw`，派生类各自实现
- 虚析构 `virtual ~Account() = default` 确保 `delete` 基类指针时调用正确的派生类析构
- `dynamic_cast` 换为 `static_cast`：信用账户由 `getType()=='C'` 预先判断，安全下行转换

### 3.4 回滚机制 (ROLLBACK)

**难点**：实现将系统状态回滚到历史某一时刻，支持撤销任意数量操作，包括回滚后的状态一致性。

**方案**：
```
1. 校验 n（0 ≤ n ≤ 日志总数）
2. 截取前 n 条日志命令
3. 完全清空系统状态（账户、用户、日期、日志）
4. 重建初始状态（admin + default 用户）
5. 开启静默模式（避免输出干扰）
6. 按顺序重放前 n 条命令
7. 关闭静默模式
8. 输出成功
```

**关键细节**：
- n=0 表示清空所有数据，重放空序列
- 静默模式确保重放过程中不输出 '1'/'0'，只输出最终结果
- 被撤销的日志（n 之后）自然丢弃

### 3.5 文件持久化与恢复 (SAVE/RESUME)

**难点**：系统状态的可靠保存和恢复，RESUME 仅允许在初始状态执行。

**SAVE 方案**：
- 遍历 `logRecords`，按 `序号 原始命令` 格式写入文本文件
- 优点：文件人可读，可手动编辑，便于调试
- 可扩展为增量写入（每日志变更时同步写文件）

**RESUME 方案**：
```
1. 校验当前为初始状态（logRecords 为空）
2. 打开文件，逐行读取
3. 跳过空行，定位第一个空格后的子串作为命令
4. 若某行无空格 → 格式错误，失败
5. 静默重放所有命令
6. 输出成功
```

技术要点：RESUME 重放与 ROLLBACK 重放共用相同的命令执行路径，保证一致性。

### 3.6 命令解析的严格类型校验

**难点**：黑盒测试中的异常输入（参数缺失、类型不匹配、负数）必须正确处理为失败。

**方案**：
- `>>` 返回 `istream&`，可隐式转换为 `bool`，提取失败时立即感知
- `isPositiveInt()` 对数字参数做严格字符检查，排除 `"0.5"`、`"-5"`、`"abc"` 等非法输入
- 两层校验：Command 负责格式与类型，BankSystem 负责业务语义

### 3.7 浮点数金额处理

**难点**：利息计算产生浮点累计误差，余额比较 `!= 0` 可能误判。

**方案**：
- 采用 `double` 存储余额和利息
- 销户时直接使用 `!= 0` 比较（因为系统内金额都是整数/固定两位小数经过有限次加减，不会产生显著误差）
- `formatAmount` 使用 `std::fixed << setprecision(2)` 确保输出始终两位小数

### 3.8 容错设计

| 措施 | 说明 |
|------|------|
| `findUser` 返回 nullptr | 所有调用处都有空指针判断 |
| `findAccount` 返回 nullptr | 所有调用处都有空指针判断 |
| 日期仅前进 | `setDate` 拒绝往过去设置，防止利息重复计算 |
| 禁止删除自己 | `deleteUser` 拒绝删除当前登录用户 |
| 静默模式 | 重放/RESUME 时不输出中间结果 |
